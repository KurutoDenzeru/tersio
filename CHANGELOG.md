## v2.26.7
 - Prices a model with the cost the host reported instead of guessing at it, which was the whole of the "these models have no price" problem. Every transcript Tersio reads already carries `usage.cost` per message — omp, pi, and opencode all write it, and no row is left without one — but `summarizeUsage` threw it away and repriced every model from LiteLLM. So `kilo/stepfun/step-5-preview` was billed $368.94 against omp's own $69.08, and twenty genuinely free models (`space-bunny`, `muse-spark-1.3-contributor`, `glm-5.3-flash`, `qwen38-flash-next`, `stealth/ox-alpha`, `MiniMax-M3`, `DeepSeek-V4-Flash`, `ling-3.0-flash-sante`, `Qwen3.8-27B` and more) each paid a $2 Sonnet default for tokens that cost nothing. On this machine the report read $373.49 where the true figure is $71.23, an overstatement of $302.27. A new `measured` tier sits above every rate card in `PRICE_TIERS_FIRM`, `usdCost` takes a measured figure, and `SessionAccum` tracks the cost per model and the message count that carried one. A model is host-priced only when the coverage counts match: a partly measured model would read its unpriced messages as zero, which is the one error worse than a guess. That a recorded zero is a real zero is not assumed — `cost_unpriced` is 0 across all 29,749 rows in `~/.omp/stats.db`, and no row is both flagged unpriced and zero, so a zero is omp's own statement that the model is free.

A test pins that.
