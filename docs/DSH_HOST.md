# DSH (DeepSeek Harness) host research — issue #68, phase 1

Answers to the six questions from [issue #68](https://github.com/KurutoDenzeru/tersio/issues/68), with a working spike. Versions: docs audit baseline `0.1.5-alpha.1`, latest npm release `0.2.1-rc.5`. Every claim below was either read from DSH's own docs or proven on this machine against a sandboxed `DSH_HOME`.

## Answers

### 1. Plugin anatomy — ship a bundle plugin

A DSH plugin is a cordis module (`export const name`, `inject`, `apply(ctx, config)`) plus the `dsh` field in `package.json`. Three forms exist; the kernel-aligned one is the **bundle plugin**: `dsh.bundle.patch` points at a `cordis.patch.yml` the package carries, `dsh plugin --profile web add` installs it with pnpm, and reconcile joins its patch layer into the profile automatically.

Decision for v1: **bundle plugin**. It installs from npm or a Git URL, needs one `dsh web` restart, and requires imports from `@deepseek-ai/cordis` (the framework is vendored and published only as `@deepseek-ai/*` scoped packages; bare `cordis`/`schemastery` do not resolve). Node requirement: `^22.19.0 || >=24.0.0`. The `dsh.client` browser half is not needed for v1 — Tersio draws nothing inside DSH's web UI. The `.dsh-plugin` directory format and the plugin panel belong to the third-party `@dsh-external/plugin-console`, not the kernel; skip it.

### 2. Mode injection — a bundle plugin hooking the agent waterfall

DSH composes its whole config tree from patch layers (profile bundles → profile patch → `$DSH_HOME/cordis.patch.yml` → `--patch` overlays), and a bundle's patch layer joins the stack on install. The plugin then hooks the agent control plane: **`agent/pre-step`** (waterfall, per-step assembly) can prepend the Caveman/RTK/Ponytail/Pstack mode blocks to every step, and `agent/session-start` covers session start. Bundle plugins load in every session of the profile, so the injection is always-on without touching files the user owns. Fallback surface: `agent/request` (request-assembly replacement) for older builds.

### 3. Usage stats — read the session logs out-of-process

DSH persists an event-sourced session log: zstd-compressed JSONL at `~/.dsh/sessions/*/*/session*.jsonl.zstd`, with `user/message`, `assistant/message`, `request/header`, `tool/call`, `tool/result`, `turn/start`, `turn/end` and more (format version 3). This is the same shape of problem as our other hosts: **Tersio's usage importer can read the logs directly, no plugin needed** — `zstdcat ~/.dsh/sessions/*/*/session*.jsonl.zstd` is the documented inspection path. A plugin can additionally subscribe in-process (`tools/result`, `agent/*`) for live capture; field-level audit of `request/header` (tokens, cost, cache, model naming) is the one open item before `agent-stats` can consume it.

### 4. Market publication — later; plain install first

A DSH market is a `format: 1` JSON index (`title`, `plugins[]` with npm/Git pinned `versions[]`, required `engines.dsh`) plus icon files, publishable on any static host such as GitHub Pages, generated by DSH's `dsh-plugin-market-index`. Browsing needs the user to enable the experimental **Custom plugin markets** bundle, add our index URL, and confirm each install. For v1: document `dsh plugin --profile web add npm:@krtclcdy/tersio-dsh` as the primary path; publish the market index as a follow-up once the plugin is on npm.

### 5. Install, detect, uninstall

- Detect: the `dsh` binary, `~/.dsh`, `$DSH_HOME`, or the **desktop app** (`~/Library/Application Support/@deepseek-ai/dsh-desktop`). On this machine the binary is **absent** — DSH runs via the desktop app and `npx @deepseek-ai/dsh` — while `~/.dsh` exists and was written to today. Detection must therefore be a disjunction that works without a binary: binary, home dir, `$DSH_HOME`, or the desktop app's data directory, any one of which counts. A binary-first check would report DSH as not installed on the very machine the phase-2 adapter will be tested on.
- Install: `dsh plugin --profile web add npm:@krtclcdy/tersio` (or `github:…`, or `link:/path` for development); takes effect after a `dsh web` restart. The npm path needs a release whose tarball carries the `dsh` bundle field — until that release ships, only `link:` to a checkout works, and the installer pins the version that does.
- Uninstall: `dsh plugin --profile web remove @krtclcdy/tersio-dsh` — reconcile is state-based, so the bundle's patch layer disappears with the package. The hand-edit write-back gap in the issue only bites manually mounted patch lines, which Tersio never creates.

### 6. RTK and tool filtering — feasible in v1

DSH exposes `tools/pre-execute` (waterfall) on every tool call: a plugin can rewrite the call, guard it, or pass it through — the same position our RTK filter occupies on other hosts. In scope for the adapter, behind the RTK mode switch.

## Spike (run 2026-11-01, sandboxed `DSH_HOME`, npm 0.2.1-rc.5 via npx)

A minimal bundle plugin — three files — installed and loaded:

```jsonc
// package.json
{ "name": "@krtclcdy/tersio-dsh", "version": "0.0.1", "type": "module",
  "main": "index.js", "exports": { ".": "./index.js" },
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } } }
```

```yaml
# cordis.patch.yml
- insert:
    - id: tersio-dsh
      name: '@krtclcdy/tersio-dsh'
```

```js
// index.js
export const name = 'tersio-dsh'
export const inject = ['tools']
export function apply(ctx) {
  console.log('[tersio-dsh] plugin loaded!')
  ctx.tools.register({ name: 'tersio_status', /* … */ async execute() { return { content: 'Tersio is mounted in DeepSeek Harness.' } } })
}
```

Commands and results:

| Step | Command | Result |
|---|---|---|
| Install | `DSH_HOME=… npx -y @deepseek-ai/dsh plugin --profile web add link:/tmp/tersio-dsh-plugin` | dependency recorded, reconcile added `@krtclcdy/tersio-dsh` to `dsh.profile.bundles` |
| Compose | `dsh web --dump-config` | composition tree shows `# == @krtclcdy/tersio-dsh` with the inserted row |
| Boot | `dsh web` | `[tersio-dsh] plugin loaded!` — `apply` ran and `tersio_status` registered |
| Uninstall | `dsh plugin --profile web remove @krtclcdy/tersio-dsh` | dependency and layer gone (state-based reconcile) |

## Phase 2 plan (follow-up issue)

The bundle plugin itself now exists on this branch: `extensions/dsh/` carries the cordis patch and the plugin module, and the root package declares the `dsh.bundle.patch`, so `dsh plugin --profile web add npm:@krtclcdy/tersio` (or `link:` to a checkout) mounts it. Proven live, with injection: a headless turn's assembly produced **23,659 chars of mode blocks** (`TERSIO_DSH_DEBUG=1` logs the assembly), and flipping the store's modes between runs changed the assembled blocks to **6,271 chars without a restart** — the provider re-reads the store at every assembly.

`HostId` gains `'dsh'`; detection is a disjunction — `dsh` binary, `~/.dsh`, `$DSH_HOME`, or the desktop app's data directory — because the binary is absent on this machine while the home dir and desktop app exist; install runs the bundle add; stats read the zstd session logs; uninstall runs the remove. One open item before stats land: field-level audit of the session-log envelope.
